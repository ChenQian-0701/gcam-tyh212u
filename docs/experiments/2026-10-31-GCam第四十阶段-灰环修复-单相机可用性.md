# 第四十阶段：移动触发灰环已修复——单相机「可用性=false」被误判为全部相机不可用

日期：2026-10-31 12:00–12:19（Asia/Shanghai）
设备：TYH212U / Android 11 / BSG MGC 9.6.080 V51
模块：`com.tyh212u.gcamhook`，新增正式修复类 `AvailabilityRepair`
构建：`lsposed-module/build/gcam-tyh212u-hook.apk`
SHA-256：`04712f9ebb59d1380655effe750733e36740a9b9e4fec0d06e695eec991feeef`（与设备已安装一致）

---

## 一、结论

**“移动手机 → 取景框出现灰环 + 快门不可用” 已修复。**

根因：GCam 的“等待相机全部可用”（`waitForCamerasAllAvailable`，类 `lnm`）在移动/会话变化时会收到
**单相机可用性样本 `[false]`**——这个“不可用”的相机正是 GCam 自己正在出流的那台。
于是“全部可用”永远不成立，`CaptureModule.setReadyState(false)` 被触发，
拍照模块 `jku` 显示灰环并禁用快门，直到超时（12–58 秒）甚至要重启应用。

修复：只把 **长度为 1 且唯一元素为 `Boolean.FALSE`** 的可用性样本改判为 `true`，其余样本原样保留。

---

## 二、如何定位到这一条（一句话版）

在 `setReadyState(false)` 的 hook 里直接打印“最近一次 `lnm` 样本与时间差”，一次灰环就得到：

```text
[attr] ready=false lastLnm(age=4ms)=input(ArrayList)=[false] caller=android.os.Kap#apply
```

即：**ready 变 false 前 4ms，`lnm` 刚好因为输入 `[false]` 返回了 false**。
这是“一对一”归因，不再依赖时间窗口统计（此前窗口内有数百条 lnm 噪声，无法判别）。

---

## 三、修复实现

`lsposed-module/src/com/tyh212u/gcamhook/AvailabilityRepair.java`

- 挂 `lnm.apply(Object)` 的 before；
- 仅当输入是 `List`、长度 1、元素为 `Boolean.FALSE` 时 `setResult(Boolean.TRUE)`；
- 默认开启；`adb shell setprop debug.gcam.fix.camavailability 0` 可关闭；
- 每次触发打一条 `[availability] single-camera unavailable -> available (N)`（前 10 次）。

设计取舍：

- **不做全局/按函数返回 true**（第三十九阶段试过，会污染其他变换的返回类型并导致应用崩溃：`Boolean cannot be cast to Long`）；
- **不动请求参数、不动谓词返回值**，只改这一种明确的误判样本；
- 多相机样本（如 `[true,false]`、`[false,false,false]`、9 元素列表）保持原样，真实可用性逻辑不受影响。

在 `HookEntry` 中的接入顺序（位于探针之前、正式修复区）：

```java
if (AvailabilityRepair.enabled()) AvailabilityRepair.install(cl);
```

## 四、验证

| 项 | 结果 |
|---|---|
| 修复前 | 移动手机 → 灰环 + 快门灰；DCIM 192 不增长 |
| 修复后（实验开关） | 移动 20–30 秒无灰环；DCIM 192 → 195（用户实拍 3 张） |
| 修复正式化后（默认开启） | 再测：无灰环；DCIM 195 → 196（实拍 1 张） |
| 触发计数 | 启动阶段即命中 11 次单相机误判样本 |
| 视图状态 | `progress_overlay=GONE`、`shutter_button=VFED` |

设备当前：`debug.gcam.fix.camavailability=1`（默认）、探针全部关闭、应用正常。

---

## 五、风险与边界

1. 该修复假设“单相机不可用样本”来自 GCam 自身占用的相机；若将来真有第二台相机被其他应用占用，
   这条判定会被忽略一次（影响面仅限该样本，不会改变多相机逻辑）。
2. 若后续发现 **2 元素**样本（`[true,false]`）也会导致灰环，需要单独分析后再决定是否纳入修复，
   当前未改动该形态。
3. 本轮只在主摄拍照模式做验证；前摄、夜视、录像等模式未回归。
